# 模拟收银台（T062）

当前默认 `MALL_PAYMENT_PROVIDER=MOCK`。无需微信商户号，不调用微信渠道，不产生真实扣款。用户于2026-11-02明确要求演示微信扫码流程；真实Native接入保留为可选模式，不能据此声称真实支付已验收。

## 操作步骤

1. 登录，选择商品、尺码与收货地址，普通购买或购物车结算；秒杀则等待异步订单创建完成。
2. 服务端先创建“待支付”订单。在订单页面点击“去支付”。
3. 选择“微信扫码（模拟）”，点击“下一步”，弹出模拟二维码；也可选择“直接模拟付款”。
4. 二维码展示不会付款。点击“模拟已支付”，服务端按原订单金额完成幂等MOCK支付。
5. 页面查询服务端订单，确认已付款后显示“模拟支付成功”。点击“查看订单”，继续演示发货与收货。

关闭弹窗或按Escape不会付款。订单超时后不能继续支付。遇到网络异常先点“查询支付结果”，沿用原订单与支付幂等键，不要重复创建订单。刷新网页后状态从服务端读取。

## 实现边界

- `MockCashier.vue`负责方式选择、二维码、显式确认、结果查询与焦点管理；普通订单和原秒杀详情共用。
- `MockCashierApi`只读取本人有效待支付订单，金额和截止时间取自数据库；不创建支付凭证、不改变订单状态。
- QR编码的是含订单号、金额和“仅演示”的普通文本，不是`weixin://`收款链接。微信扫码无法付款，也无需实际扫码。
- 确认复用原`Retail`/`Orders`的MOCK事务、所有权、超时、幂等校验；不能仅凭前端点击展示成功。
- WECHAT模式及已有微信支付意图的订单拒绝模拟入口；真实支付组件和模拟收银台分开。
- 退款规则仍见[模拟支付说明](MOCK-PAYMENTS.md)和[普通商城说明](ORDINARY-SHOP.md)。
