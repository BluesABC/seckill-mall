# 演示与项目讲解

关联T040。证据以[PROGRESS](PROGRESS.md)为准，运行步骤见[DEPLOYMENT](DEPLOYMENT.md)，本机完整商城http://localhost:18080。

## 五分钟演示

1. 启动商城，展示SNKR//DROP运动鞋首页、手机布局、分类/详情和真实EU尺码。未上架码置灰；清单仅记录逐款抢购意向，不占库存或合并结账。
2. 注册普通用户，选择有效场次，按图片输入验证码。页面显示“受理/排队”，解释Redis预扣成功还不等于MySQL订单或支付成功。
3. 等待待支付订单，用MOCK支付并刷新。支付次数、状态与归属由Java/MySQL兜底。客户端保存同一个requestId与支付幂等键；网络失败不能换ID重复抢。
4. 查看另一笔未支付订单的关闭结果，展示库存回补证据。演示环境默认15分钟过期；不要在日常库手工改订单时间。快速关闭夹具仅在独立验收测试里使用。
5. 用ADMIN查看商品/活动和恢复记录，运行只读对账。结合S7的真实故障/超卖/压测数据讲削峰和收敛，避免把快速拒绝QPS说成订单TPS。

## 可用证据支持的讲解

| 机制 | 代码入口 | 说明 |
| --- | --- | --- |
| Redis Lua原子预扣/限购 | src/seckill/lua/reserve.lua | 库存、资格、请求和待发事件同一次原子写；后接同连接AOF屏障 |
| 不确定投递恢复 | src/mq/relay_worker.cpp | pending事件用官方C++ SDK至少一次投递；确认未知不盲回补 |
| MySQL订单幂等 | src/order/.../Orders.java | 先锁库存父行，唯一请求/资格、条件扣库存、订单与outbox同一事务；提交后ACK |
| 支付/关闭竞争 | Orders.pay / closeExpired | 同一状态与父锁竞争；已支付不回补，关闭产生唯一事件 |
| 恢复/死信 | Workers.recover / replay | 过期请求写持久终止事实后回补；迟到原事件不能复活 |
| 只读对账 | scripts/reconcile.py | 去重预留、解释在途差额，检测稳定差异；变化/不可达不伪装正常 |
| 部署与测试 | deploy/compose.yml / tests | 真实Redis/MySQL/RocketMQ，WSL原生入口、单Broker、容器重启与私有故障夹具 |

图表和指标直接引用阶段报告，不另造“百万QPS”“零延迟”“exactly-once”。容量结果需同时说明样本量、并发、时长、受理与落库比例、P95/P99及硬件；短突发不能证明长稳态上限。S7用户选择本机探索基线，不是已冻结生产容量目标。

## 当前交付边界

MOCK支付、单Redis/MySQL/Broker、本机HTTP、无生产HA/备份恢复声明。图片验证码没有非视觉替代；多规格创建、目录分页、原图压缩、普通购物车/合单与优惠券仍未实现。永久Redis数据丢失会告警/拒绝，而不会自动从初始库存重置。真实支付、TLS、资源预算、长时压测和生产恢复SLA应按业务计划继续验收。
