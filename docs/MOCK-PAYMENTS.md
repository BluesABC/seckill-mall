# 秒杀模拟支付演示

本文描述原秒杀订单的模拟支付/财务退款。普通订单的未发货取消型退款及物流见[普通商城说明](ORDINARY-SHOP.md)。

本功能不调用支付渠道，不产生真实扣款或退款，不属于真实收款系统。

## 用户流程

登录并抢购 → 等待订单创建 → 订单详情点击“去支付” → 选择“微信扫码（模拟）” → “下一步”展示演示二维码 → 点击“模拟已支付” → 服务端确认成功 → 查询支付凭证。完整收银步骤见[模拟收银台](DEMO-CASHIER.md)。随后可点击“模拟全额退款”并确认，展示唯一退款凭证。刷新继续从服务端查询。秒杀财务退款仅限全额且仅一次，不自动恢复库存和秒杀资格；退货/再次购买不在本阶段范围。

## 实现与边界

Java在事务内先锁活动库存父行，再锁订单，沿用支付/关单锁序。支付读取订单金额和MySQL时钟，原payments凭证不覆盖；mock_refunds的payment_id唯一且引用支付凭证。每次退款锁内检查已付款及MOCK来源，已有退款直接返回，网络失败后可安全重试。订单保持PAID以保留履约与库存占用事实，paymentState单独呈现REFUNDED。

`004_mock_refunds.sql`是增量迁移，禁止改旧SQL校验和。更新容器时先构建tools/migrate、order、gateway，执行迁移，再更新业务容器；不要跳过迁移启动新版本。退款回滚业务版本时保留新增表和凭证，不删除数据。新增读接口不会返回其他用户的凭证。

## 只读对账

在已配置数据库环境的工具容器或WSL中运行 `python scripts/reconcile-payments.py`。使用一致性只读事务，比较支付金额/订单状态、已付款缺失凭证、退款金额/来源，CLEAN退出0，DRIFT退出1。只检查本地MOCK账本，没有外部账单，不能称为渠道对账；不自动修数据。

## 验证入口

- `bash scripts/test-s4.sh`：真实HTTP、C++、RocketMQ、MySQL、Redis业务回归，包含并发退款/越权/未支付拒绝/退款后支付重放、库存不变与对账漂移检测。
- `bash scripts/build-web-wsl.sh` 后 `source scripts/env-wsl.sh && node tests/browser/mock-payment.mjs`：页面夹具验证凭证、取消确认、退款、刷新和手机/桌面布局；它不能替代真实交易验收。

真实支付、渠道回调、拒付、部分退款、退货入库与自动续购均未接入。
