## 接口和部署交付标准

- API 契约说明认证、输入输出、状态码、错误码、幂等标识、活动时间、限购规则和状态查询方式；请求中的 userId 不能替代认证身份。
- 轮询有退避、超时和终态；前端置灰只改善体验，服务端仍须拒绝重复/非法请求。
- 数据表含主外键关系、业务唯一索引、状态与版本字段、库存非负保护、事务边界和必要查询索引。订单金额使用明确整数最小货币单位或定点类型。
- 提供环境变量示例、初始化/迁移/种子数据、服务健康检查、依赖就绪重试、持久化卷、日志与故障排查说明。Compose 启动顺序本身不能保证服务就绪。
- 从干净环境按文档启动，演示商品 → 秒杀 → 排队 → 待支付 → 支付或超时关闭。记录实际执行结果；Docker 不可用时保留配置并报告未验证部分。

## 功能与故障验收矩阵

| 场景 | 必须验证的结果 |
| --- | --- |
| N 件库存、超过 N 个不同用户同时抢购 | 库存不为负；有效订单不超 N；无越权、活动时间或价格绕过 |
| 同用户多次/多连接抢购 | 同一资格最多一个有效订单，重复调用返回可解释结果 |
| 同 requestId 重复投递、消费与重放 | 仅一次库存扣减/创建；身份或参数冲突不冒充成功 |
| 预扣后崩溃、确认丢失、MQ 重启 | 已受理请求可追踪；无永久孤立预留；消息重投安全 |
| DB 写入失败、提交后消费者崩溃 | 可恢复重试；ACK 时机正确；无重复扣减或有效订单 |
| MQ 堆积、DB 限速或不可用 | 有界背压、可观测积压与拒绝；恢复后按约定时间排空 |
| 未支付超时、重复关闭与重复回补 | 正确归还资源且只一次；资格策略一致 |
| 支付和超时同时发生、迟到回调 | 状态转换唯一；已支付不回补；迟到支付明确处理 |
| Redis 数据丢失/重启与服务恢复 | 按声明故障模型恢复；不会盲目重置库存或丢失购买事实 |
| 库存/订单异常注入与对账 | 区分在途与异常；告警或幂等补偿可审计 |
| 验证码/地址令牌重放、限流绕过 | 服务端验证活动/用户绑定和有效期；过期或非法请求被拒绝 |

## 压测规范

容量目标未确定前，进行可复现基线与容量探索，报告测得上限，不宣称满足未知指标。正式达标前确认并冻结目标 QPS、并发、P95/P99、失败率和恢复窗口。

报告必须记录：代码版本、构建参数、硬件/容器资源、实例数、网络拓扑、组件版本、压测工具、连接模型、用户数、库存、冷热缓存、活动/SKU 分布、请求组成、阶梯/突发/持续负载、时长、重复次数与原始结果路径。

分别统计：入口 QPS、限流/售罄/资格拒绝 QPS、预扣接受 QPS、订单持久化 TPS、支付/关闭吞吐、各类成功/失败/超时。记录响应和端到端下单 P50/P95/P99、CPU/内存/连接池、Redis 延迟、MQ 积压/最老消息年龄、消费重试/死信、DB 锁等待，以及对账/补偿滞后。

至少覆盖单热点 SKU、多个活动、突发流量、持续负载与下游故障恢复。业务拒绝和系统错误分开统计；不能在售罄后快速拒绝的大量请求上证明订单吞吐。压测结束后等待约定收敛窗口，核对库存守恒、有效订单唯一性、无超卖、无重复回补和无永久悬挂请求。
