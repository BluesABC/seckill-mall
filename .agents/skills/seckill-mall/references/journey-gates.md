# 混合API旅程验收

- 使用`bash scripts/test-s19-journeys-wsl.sh`，只允许自有S7保留卷；共用容量锁，退出恢复原C++线程/队列，运行期间不要并行故障或重建。日常演示栈不参与注入。
- 区分15次/秒背景读与64条/30分钟完整旅程。账号的预置bcrypt哈希不等于真实注册；真实注册、登录、验证码生成/兑换、下单与MOCK支付各自统计。不要放宽认证频控来迎合测试流量，不预置会话伪装真实登录。
- 图片验证码只在隔离夹具设置答案摘要、保留KEEPTTL；可读题目按接口题面正常作答。保留60秒证明、15分钟待支付。16笔订单自然关闭，48笔模拟支付并重复提交，库存守恒与支付唯一性必须核对。
- 三个活动独立只读对账；大历史数据使用活动范围与显式上限，避免默认50,000行保护误伤。不能清空历史订单或延后旧订单过期来取得成绩。
- 64人瞬时提交，分别给64/32库存；后者必须区分32次售罄和技术错误，不计算拒绝QPS来宣称交易能力。准备验证码/令牌与同时提交分别说明。
- 短自检标记`smokeOnly`；独立`check_journey_gate.py`拒绝短窗口、缺失接口/库存明细、错误状态、重复支付或改变TTL。异常中止不视为通过，不公开登录令牌或密码。
- 详细工况见项目`docs/S19-TEST-PLAN.md`；本机结果不替代生产SLA、HA、支付渠道或人工读屏验收。接口/服务代码没改动时无需为测量重复整套故障测试；改变关键路径后按capacity-gates参考做必要回归。
